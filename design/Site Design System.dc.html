pinchos web design system · v1 ← landing page

Everything the site is allowed to do.

Scope: the website only. The product's own design system (menus, markers, states) lives in design/docs/design-system.md — the site quotes the product, never restyles it.

1 · Principles

Paper, not chrome. Ivory background, ink text, hairline rules. No gradients, no glass, no dark mode in v1.
The product is the only dark surface. Menu-bar mockups and code blocks sit on charcoal; nothing else does.
One accent per block. Terracotta is interactive, olive is labels. Never both carrying meaning in the same block.
Write like a README. Matter-of-fact, lowercase “pinchos”, no exclamation marks, no superlatives.

7 · Voice

say
“pinchos runs the commands you give it.”
“Failed 2 minutes ago — exit 1.”
“Free, open source, native AppKit.”
don’t say
“Supercharge your workflow! 🚀”
“Something went wrong.”
“The ultimate menu bar experience.”
Sentence case, present tense, no exclamation marks, no emoji. Error examples in copy are always real ones with exact causes. Feature claims name the mechanism (NSMenu, json, template icons), not the feeling.

8 · Adding pages later

Every new page reuses the landing nav and footer verbatim. Docs pages: single column, max-width 720, body 16.5/1.65, H2s in serif with 56px top spacing, code blocks per §6. A changelog or blog gets mono dates in olive and serif titles. If a page needs a component this system doesn't define, add it here first — one page, one new component, maximum.
